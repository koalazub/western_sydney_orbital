Open the flight lab

The editable Marimo notebook runs on your machine. The hosted game does not contain a shared Python kernel.

  1. From your repository directory, start the lab and local game:
devenv up lab simulation
  1. Open the local game, or the game address printed by Devenv if you changed its port.
  2. Use Open notebook in that game. It opens the authenticated local editor when the lab is ready.

Keep the game visible in a separate window. In the notebook, use Connect to show Python guidance, then Run controller when you want it to fly. Live tuning does not reset the current flight.

If the editor is still unavailable, check its output with devenv processes logs lab. Keep its login token private.

You can return to your existing game window without closing or resetting its simulation.

Fly the hosted game with Python

The hosted game can connect to a private Python process on your machine through an authenticated room. Create a room from your repository directory:

devenv shell uv run --locked wsorb room create --connection-file .devenv/wsorb-room.json

Open the private link it prints in a new tab and choose Allow Python connection. This starts a separate game; leave existing flights open. Keep the new game visible in a separate window, then run:

devenv shell uv run --locked wsorb checkpoint --room-file .devenv/wsorb-room.json --run --progress

This flies the portable checkpoint policy, not the notebook's default route policy. No flight is reset or tuned. Keep the link and connection file private. Your Python source is not uploaded. Manual ship input or pausing ends the run; a network delay can expire a command and end the attempt.
